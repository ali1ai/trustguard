# TrustGuard Architecture Roadmap

## Product boundary

TrustGuard is a research and portfolio platform for helping a trust-and-safety team triage user-generated content. It is not an autonomous punishment system. The default public demo should not retain submitted content, should not expose reviewer endpoints without authentication, and should not require an external LLM API key for its baseline path.

## Runtime architecture

```text
Content submission
    |
    v
Input validation and safe normalization
    |
    +--> Spam classifier (trained local ML artifact)
    |
    +--> Toxicity classifier (trained local ML artifact; one signal)
    |
    +--> Fast heuristics / optional provider moderation
    |
    v
Contextual policy analyst (optional LLM, conditional invocation)
    |
    v
Policy auditor (only for uncertainty, conflicts, or high-risk cases)
    |
    v
Deterministic policy engine
    |---- allow
    |---- label
    |---- soft_hold (reversible)
    |---- queue_review
    v
Structured response, redacted audit metadata, evaluation/monitoring
```

The deterministic policy engine owns action selection. LLM agents return typed assessments and evidence; they do not directly execute irreversible actions. Disagreement or uncertainty should increase review priority rather than grant the more punitive action.

## Component responsibilities

- **API / input validation:** enforce content length/type limits; use generic error responses; avoid logging submitted text by default.
- **Local detectors:** return separate model scores and thresholds, not a misleading combined "probability". Models must include dataset/version provenance.
- **Contextual policy analyst:** assess the message in relation to a versioned policy; distinguish direct abuse from quoted/reporting/educational/counterspeech contexts.
- **Policy auditor:** independently check selected uncertain or conflicting cases; if unavailable, degrade safely to human review for high-risk ambiguity.
- **Deterministic policy engine:** apply versioned thresholds and action constraints; do not let untrusted text override system instructions or policies.
- **Human review:** show the content, category evidence, model signals, policy version, and reason for escalation. Capture reviewer corrections only with explicit storage and access controls.
- **Evaluation and observability:** log timings, model versions, action counts, error rates and aggregate outcomes; avoid retaining raw text by default.

## Data and model boundaries

- Raw datasets are downloaded at experiment time and excluded from Git.
- Training artifacts are generated by trusted training workflows. Never load user-supplied `joblib`/pickle files; deserialization can execute code.
- Publish model cards and aggregate reports; keep row-level error files local by default.
- Classifier thresholds are selected on validation data. The test partition is held out until final evaluation.
- The binary toxicity model is only one signal; taxonomy-specific subtype classifiers and contextual agents are separate components that must be evaluated separately before runtime integration.

## Experiment sequence

1. **Spam baseline:** SMS spam vs ham. Validate the data and model-artifact pipeline.
2. **Toxicity baseline:** Civil Comments primary toxicity plus separate subtype models. Compare word-only and word+character TF-IDF.
3. **Subgroup robustness:** use an identity-annotated dataset and report subgroup support, false-positive gaps and uncertainty. Do not infer fairness from overall scores.
4. **Contextual challenge set:** quoted abuse, counterspeech, benign identity discussion, satire, threats, adversarial spelling, and prompt injection.
5. **Agent ablations:** classifier-only vs LLM-only vs hybrid; add the auditor only where conditional evaluation suggests benefit.
6. **System evaluation:** latency, API/model cost, failure modes, queue precision, reviewer overturn rate, and versioned regression tests.

## Public demo safeguards

- Demo is explicitly labeled a research prototype.
- No automatic user bans or permanent deletion.
- Default content persistence is off.
- External API calls are opt-in, with rate and cost controls before public activation.
- Restrict or disable human-review administration endpoints on the public demo unless authentication is configured.
- Use safe examples in the default interface; avoid rendering submitted text as raw HTML.
- The demo reports model scores as model scores, not calibrated probabilities unless calibration has been separately tested.
